# 설계와 판정 기준

## 구조

- `NikkeSafetyCheck.Core`: 플랫폼 독립 엔진. 스캔, 판정, 계획, 조치, hosts 변환, 보고서.
- `NikkeSafetyCheck.Windows`: 레지스트리, SID, 서명, 파일 ID, 방화벽, Defender, 관리자 보조.
- `NikkeSafetyCheck.UI`, `NikkeSafetyCheck.App`: .NET 10 LTS + WPF. self-contained 단일 실행 파일.
- 흐름: `Scan -> Findings -> Immutable Plan -> 사용자 선택 -> Apply(직전 재확인) -> Verify`.

.NET 10은 2028년 11월까지 지원되는 LTS이고, WPF는 외부 런타임 없이 단일 파일로 배포할 수 있어 프롬프트의 기본안을 그대로 택했습니다. .NET 8은 2026년 11월 지원이 끝나 제외했습니다.

## 결과 기록

모든 검사 결과는 `ruleId, sourceUrl, ruleVersion, observedAt, userSid, evidenceType, confidence, status, remediationEligibility`를 가집니다. 상태는 `Found/NotFound/Unknown/NotApplicable`입니다. 위험도(`OverallRisk`)와 완료 여부(`Completeness`)는 별도 축으로 계산합니다.

## 판정 기준

| 증거 | 등급 | 조치 자격 |
|---|---|---|
| 설치 폴더 `debug.log`의 콘솔 줄 `k2f_chan registered`, `agent started as` | 고위험(과거) | 해당 없음 |
| `leveldb`의 `k2f.agent.state` | 고위험(과거) | 해당 없음 |
| 알려진 해시 DLL | 고위험(현재) | 가능 |
| 정확한 구조의 DLL + 그 DLL을 가리키는 사용자 COM | 고위험(현재) | 둘 다 가능 |
| Chrome의 정확한 구조 + 폴더명이 파일 SHA-256과 같음 + 유효 서명 아님 | 고위험(현재) | 가능 |
| 사용자 COM 값이 정확한 구조이나 DLL 없음 | 고위험(과거) | COM만 가능 |
| 메모리에 정확한 구조 경로의 모듈 로드 | 고위험(현재) | 수동 |
| 콘솔 형식 아닌 지표 문자열, 소스가 빈 로더 메시지 | 의심 | 없음 |
| tinyget의 `insight.bundle`, `k2f*.lua` | 의심 | 없음 |
| `k2f.agent` 단독, 로더 캐시 주소 | 의심 | 없음 |
| 구조나 이름이 다른 같은 이름 DLL, 유효 서명 DLL, 다른 브라우저 단독 DLL | 의심 | 없음 |
| 사용자 COM이 다른 경로를 가리킴, 다른 CLSID 변종 | 의심 | 없음 |
| 임시 파일 이름, 지표 IP 연결, DNS 캐시 | 의심 | 없음 |
| 수동 선택 로그 | 최대 의심 | 없음 |

쓰지 않는 근거: 정상 EXE, `LoadFeatures`, 부모 폴더 존재, HKLM의 같은 CLSID, 프로세스 이름, 해시 불일치, `FETCH_LIST suc success`, `onominan.tmp`.

프롬프트와 다르게 판단한 곳은 두 군데입니다. 이유는 [SOURCES.md](SOURCES.md)에 적었습니다.

1. `k2f.agent.state`를 '캐시 문자열'(의심)이 아니라 고위험으로 처리합니다.
2. DLL이 사라진 COM 잔여물은 값 구조가 완전히 일치할 때 제거 대상에 넣습니다. 임의 경로를 가리키는 단독 키는 여전히 제거하지 않습니다.
3. COM 연결이나 알려진 해시가 없어도, Chrome 경로의 정확한 파일 이름 + 64자리 폴더 + 폴더명과 파일 해시 일치 + 유효 서명 없음이 모두 맞으면 '충분히 검증된 결합 증거'로 봅니다. 공개 보고에서 DLL이 피해자별로 달라 해시 목록만으로는 잡히지 않기 때문입니다. 체크를 끄면 격리하지 않습니다.

## 최소 권한

- 매니페스트는 `asInvoker`입니다. 점검과 사용자 범위 조치는 일반 권한으로 실행합니다.
- 사용자 COM과 DLL 조치는 **대상 사용자 본인의 일반 프로세스에서만** 합니다. 다른 관리자 자격으로 실행하면(세션 소유자 SID와 토큰 SID가 다르면) 대상은 세션 소유자로 유지하고 사용자 조치를 계획에서 뺍니다.
- 레지스트리는 `HKU\<SID>_Classes` 실제 하이브 경로로 읽습니다. HKCU/HKCR 병합 보기를 쓰지 않습니다. 미로드 하이브는 자동 로드하지 않고 미검사로 보고합니다.
- 관리자 동작(방화벽, hosts, Defender 오프라인)은 같은 exe를 `runas`로 실행합니다. 고정 동사 4개만 받고, 차단 값은 내장 IOC에서 읽습니다. 호출자에게 받는 값은 런처 경로 하나이며 `IsValidLauncherExecutable`로 다시 검증합니다. 파이프는 결과 전달 전용이고 명령을 읽지 않습니다.

관리자 보조는 사용자 임시 폴더에서 불러온 모듈이 있으면 아무것도 바꾸지 않고 멈춥니다. PowerShell은 시스템 모듈 경로만 쓰도록 고정합니다.

알려진 한계: self-contained 단일 파일은 일부 네이티브 라이브러리를 사용자 임시 폴더에 풀어 실행합니다. 이미 사용자 권한으로 침해된 세션에서는 공격자가 이 프로그램을 포함해 무엇이든 변조할 수 있으므로, 이 도구의 결과를 절대적 근거로 삼으면 안 됩니다. UAC 승인 시 표시되는 게시자 정보도 없습니다(코드 서명 없음).

## 조치 안전장치

- 실행 직전 재확인: 경로 구조, reparse 체인, 값, SHA-256, 파일 ID, SID. 다르면 `Aborted`.
- 거부: UNC, `..`, 장치 경로, 대체 데이터 스트림, junction, symlink.
- HKLM 쓰기는 API 수준에서 예외. 키 삭제는 빈 키만 가능하고 트리 삭제 API를 쓰지 않습니다.
- 증거 보존이 실패하면 변경하지 않습니다.
- 격리 파일은 `.quarantined` 이름과 실행 권한 없는 ACL을 가집니다. 공유 보고서에 내용이 들어가지 않습니다.
- `.reg` 백업을 만들지 않습니다. 기록은 JSON입니다.
- 저널은 항목별로 플러시하므로 앱이 꺼져도 어디까지 했는지 남습니다. 다음 실행에서 안내하고, 재점검으로 현재 상태 기준의 새 계획을 만듭니다.
- hosts는 변경 전 파일을 옆에 `hosts.NikkeSafetyCheck.bak`으로 남기고 내용만 다시 써서 ACL을 유지하고, BOM과 ANSI 바이트, 줄바꿈을 보존합니다. 표식이 손상되면 수정하지 않습니다. hosts는 와일드카드를 쓰지 않습니다.
- 방화벽은 도메인이 아니라 IP로 규칙을 만들고, 고유 이름과 그룹으로 관리합니다. 프로세스 이름 일괄 차단을 하지 않습니다.

## 개인정보

- 텔레메트리, 자동 업로드, 자동 업데이트, IOC 도메인 접속·DNS 질의가 없습니다. VirusTotal로 자동 전송하지 않습니다.
- 브라우저 `Login Data`, `Cookies`, 암호 저장소, Claude 인증 파일, SSH 개인키를 열지 않습니다.
- 로그에서는 지표 개수와 시각만 뽑습니다. 원문, 컴퓨터 이름, UUID를 결과에 담지 않습니다.
- 공유 보고서는 사용자명, PC명, SID, 경로 일부, UUID, 긴 16진수, URL 쿼리, Bearer, key=value 비밀을 가립니다. HTML은 모두 이스케이프하고 CSP로 외부 리소스를 막습니다.

## IOC 데이터

`Data/iocs.json`은 출처, 관찰 시점, 재검토 시점을 가진 선언적 데이터입니다. 모르는 필드, 경로형 접두사, 잘못된 도메인·IP는 로드 단계에서 거부합니다. 삭제 경로는 코드에 고정되어 있고 IOC에서 받지 않습니다. 코멘트로만 보고된 `89.126.250.172`는 차단 목록에서 제외하고 연결 조회에만 씁니다.
